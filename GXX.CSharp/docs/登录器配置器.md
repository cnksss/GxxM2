# GXX 登录器配置器（ClientData.dat 生成器）

> 重建自 GXX 套件的登录器配置器。产出物为客户端 `ClMain.LoadConfig` 读取的
> **配置数据文件**（真机名 `ClientData.dat`，即 `TClientParam.sClientDataFile` 指向的文件）。
>
> 全部格式结论均**由真机文件实测得出**，不是推测。关键验证记录见文末。

---

## 1. 它解决什么问题

GXX 原仓库只有 9 个可执行程序（客户端 + 8 个服务端），**没有**登录器、也没有登录器配置器。
但客户端源码里完整保留了与登录器的全部接口契约，而线上真机又存在配置文件本体。
本工具即据此重建的配置器。

工作流：

```
选择模板 ClientData.dat  →  读入设置  →  修改各项  →  生成新的 ClientData.dat
```

**为什么用「模板 + 字段编辑」而不是从零合成**：线上运行的客户端是**比仓库源码更新的修订**
（记录 23324 字节，比源码声明多出若干字段）。本工具只改写已实测校准的字段，
**未映射字段保持字节不变** —— 兼容性风险为零。

## 2. 快速开始

### 图形界面

```
GXX.CSharp\src\GXX.Configurator\bin\Release\net8.0-windows\GXX登录器配置器.exe
```

1. 「选择模板…」指向一份可用的 `ClientData.dat`（例如线上客户端目录里的那一份）
2. 工具会自动「读入设置」并刷新「payload 段落」页
3. 在「基本设置」「客户端选项」「界面文字」中修改
4. 指定输出文件 → 点「★ 生成」
5. 看底部日志：出现「★★★ 生成成功，回读校验通过」即成功

> ⚠ 生成前请备份线上 `ClientData.dat`。

### 命令行

```bat
:: 查看用法
GXX登录器配置器.exe --help

:: 生成（沿用模板内的设置，可用于无损校验：输出应与模板逐字节相同）
GXX登录器配置器.exe --build 模板ClientData.dat 输出.dat

:: 生成（套用外部设置文件）
GXX登录器配置器.exe --build 模板ClientData.dat 输出.dat settings.ini

:: 导出已校准字段的当前值（调试用）
GXX登录器配置器.exe --dump ClientData.dat dump.txt
```

### 作为类库

```csharp
using GXX.Core.Launcher;

// 读取既有配置
LauncherSettings s = ClientDataBuilder.ReadSettings(@"D:\...\ClientData.dat");
s.GamePlanFile = "NewopUI.Pak";
s.RunGatePassword = "MyGatePwd";
s.ClientConfigs[3] = true;               // 下标语义见 CheckboxNames

// 生成（可选替换背景图/光标）
var result = ClientDataBuilder.Build(
    templatePath: @"D:\...\ClientData.dat",
    settings: s,
    outputPath: @"D:\...\ClientData_new.dat",
    backgroundBmp: File.ReadAllBytes(@"logo.bmp"));
foreach (var n in result.Notes) Console.WriteLine(n);
```

## 3. 文件格式（实测确认）

```
+--------------------------------------+ 0
| payload 区（各段 zlib 数据）           |
+--------------------------------------+ nSize
| TConfigClient 记录（DES 加密）         | SizeOf(TConfigClient) = 23324（真机实测）
+--------------------------------------+ 文件末尾
```

| 项 | 值 / 算法 | 依据 |
|---|---|---|
| `nSize` | payload 字节数 | `ClMain.pas:2968` |
| `nCrc` | **`CheckCrc.pas` 变体**：初值 `$DBC66688`（≠ 标准 `$FFFFFFFF`），表为标准 zlib 表（多项式 `$EDB88320`） | `Common\CheckCrc.pas:119,123,154` |
| 记录加密 | DES-CBC，**块大小 BS = 20**（不是 8），IV 由 `SHA1(key)[0..8)` 经 `DoInit`+`EncryptBlock(全 $8F 的 IV)` 导出 | `Common\UnitDes.pas:48,810-827` |
| 密钥字符串 | **`"3230393649"`** = `IntToStr(NewEncryKey^)`，`NewEncryKey^ = $0C08BE531`。注意走的是**无符号 Int64 重载**（有符号的 `-1064573647` 解不开真机文件） | `UnitDes.pas:1109` |
| payload 各段 | zlib 流（`78 9C` 头） | 实测 6/6 段 |
| 段落 Crc | `CheckCrc.Crc32` over **解压后**数据 | 实测 `nBackBmpCrc = 0xD4535EA7` 与解压后图片完全一致 |

### 已实测校准的字段偏移

字段区上界 `KnownFieldsEnd = 4509`；其后到记录末尾存在未映射字段，原样保留。

## 4. 与原版代码的互通性

本工具是 **C# / .NET 8 重写**（原仓库没有配置器源码，因此是**按格式证据重建**，不是移植）。
互通性分层面如下，全部有实测证据：

| 层面 | 互通 | 证据 |
|---|---|---|
| **产出的 `ClientData.dat`（二进制）** | ✅ **完全互通** | ① 真机文件（由原版 `MakeGameLogin.exe` 2024-06-13 生成）解码→再编码 **211,475 字节逐字节相同**；② 不改任何设置直接生成，**输出与真机文件哈希相同** ⇒ 本 C# 编码器与原版编码器**字节级等价** |
| **原版 `Config.ini`（设置文件）** | ✅ **完全互通** | C# 的 `LauncherSettings.LoadIni` 直读原版 `Config.ini`，所得值与真机记录实际字节 **158/158 项吻合** |
| **字段偏移语义** | ✅ **完全互通** | `ClientConfigs[0..100]` 与 `Checked0..Checked100` **101/101 一致**；52 个字符串字段按值定位全部命中 |
| **客户端读取路径** | ✅ **完全互通** | `DecryptDes(密钥 "3230393649")` + `CheckCrc($DBC66688)` + zlib + 段落 CRC(对解压后数据) 逐项实测对齐 |
| **启动参数通道 `TClientParam`** | ✅ **算法互通** | 编解码通道自检全通过；仅 `SizeOf` 缺一次二进制确认（见 §6） |
| **作为 Delphi 组件直接调用** | ❌ 不适用 | 跨语言。需要时用 **CLI 子进程**：`GXX登录器配置器.exe --build 模板 输出 settings.ini` |
| **生成登录器 EXE 本体** | ❌ **未实现** | 原版 `MakeGameLogin.exe` 还负责皮肤叠加、图标替换、加壳（WinLicense）。本工具只做**配置数据**部分 |

复现互通测试：

```bat
cd _analysis\ClientDataKit
dotnet run -c Release -- ini      :: 原版 Config.ini ↔ 真机记录，逐项比对
dotnet run -c Release -- verify   :: 解码→再编码逐字节往返
```

## 7. 登录器 → 客户端 启动参数（`TClientParam`）

配置器只管"配置"，**启动参数是登录器运行时的职责**，但算法已实现并自检通过，登录器可直接复用。

```
Client.exe  0  <arg1>  <arg2>          ← 三方登录器模式（Client.dpr:575）
arg1 = EncryString_LF(IntToStr(pKey))                      会话随机码
arg2 = zEncryBufferK(TClientParam字节, SizeOf, GetKeyValue(pKey))
```

```csharp
var p = new LauncherParam {
    ServerAddr = "127.0.0.1", ServerPort = 7000,
    ServerCaption = "我的传奇",
    ClientDataFile = @"D:\...\ClientData.dat",   // 配置器产出的文件
    ScreenWidth = 1024, ScreenHeight = 768, BitCount = 32, WindowMode = true,
    MaxClientCount = 2, SemaphoreName = "GXX_SEM", MachineID = "...",
    UpdatePassWord = "APEXM2",
};
int pKey = EncryptUnit.GetKeyValue();
var (arg1, arg2, _, _) = p.Encode(pKey);                 // 三方模式
string cmd = LauncherParam.BuildCommandLine(arg1, arg2, true);
// → CreateProcess(Client.exe, cmd, ...)
```

**为什么只能用三方模式**：标准模式需要 `Common\DesUtils.pas` 的 `EncryptDes_New`，该单元**不在本仓库**——
客户端作者正是为此预留了三方模式（`Client.dpr:574`「用于三方登录器，因为不想提供 EncryptDes_New 的代码」）。
标准模式调用会抛 `NotSupportedException`。

> ⚠ **`SizeOf(TClientParam)` 尚需一次二进制确认**：记录含 `sDomainName: array[0..999] of Char`，
> 非 Unicode 下为 **2333** 字节（当前默认），Unicode（Delphi 2009+）下为 **3333** 字节。
> 仓库内其它实测证据（枚举 1 字节、ShortString 走 AnsiChar 语义）指向非 Unicode，
> 但线上 `Client.exe` 尚未找到，无法反查。若客户端收不到参数，把 `CharWidth` 改成 2 即可。

> 🐞 **发现 GXX.Core 既有实现的一处潜在缺陷（未修，避免破坏既有测试）**：
> `EncryptUnit.zEncryBufferK` / `zDecryBufferK` 把 EDcode(6bit) 的**二进制**输出经 **GBK** 做字符串往返，
> 非法 GBK 序列会被替换 ⇒ **有损**（ASCII 小样本下看不出来）。
> Delphi 的 `AnsiString` 在此只是字节容器，正确映射是 Latin-1。
> 已在本套件提供字节安全实现 `LauncherCrypto.ZEncryBufferK / ZDecryBufferK`。
> 现有 `EncryptUnit.z*` 目前只定义、无调用者，故不影响线上路径。

## 8. 尚未覆盖（后续可做）

1. **记录中段未映射字段**（4509 之后约 380 字节 + 中段 284 字节）：
   如「数值单位显示」「微端状态」「背包对比动画」等较新选项。
   需要更多锚点或用两份不同配置做差分才能定位。
2. **payload 段落的语义命名**：目前只标定了 5 个 UI 段 + 背景图 + 3 个光标。
   其余（自定义怪物/技能/NPC、物品描述、文件列表等）未逐一识别。
3. **`SizeOf(TClientParam)` 的二进制确认**（见上）。
4. **生成登录器 EXE 本体**（皮肤叠加、图标替换、加壳）：
   与 BlueCodePXL_415 的 overlay 模型不同，需要另行设计。
5. **既有 flaky 测试**：`GXX.Integration.Tests` 两个用例并发绑端口，偶发失败（与本次工作无关）。
